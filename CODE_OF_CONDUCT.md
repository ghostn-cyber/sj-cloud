# SJ Cloud Code of Conduct

> Professional standards for collaboration within the SJ Cloud engineering ecosystem.

---

# Purpose

SJ Cloud is a professional engineering platform dedicated to building secure, scalable, and reliable cloud infrastructure.

This Code of Conduct establishes the behavioral expectations for everyone participating in the project, including employees, contractors, partners, contributors, reviewers, and maintainers.

The objective is to foster an engineering culture built on professionalism, technical excellence, accountability, and mutual respect.

---

# Scope

This Code of Conduct applies to all project-related activities, including:

- Source code contributions
- Documentation
- Architecture discussions
- Issue tracking
- Pull requests
- Code reviews
- Design reviews
- Security discussions
- Operational planning
- Internal and external communications
- Meetings and workshops
- Community discussions

---

# Core Values

All participants are expected to uphold the following principles.

## Professionalism

Communicate respectfully and professionally.

Focus discussions on technical merit rather than individuals.

---

## Integrity

Be honest about:

- Technical limitations
- Risks
- Mistakes
- Security concerns
- Operational impacts

Engineering decisions should never intentionally misrepresent facts.

---

## Respect

Treat every participant with dignity regardless of:

- Experience level
- Role
- Employer
- Organization
- Background
- Nationality
- Identity
- Technical preference

Disagreement is acceptable.

Disrespect is not.

---

## Collaboration

Engineering is a team effort.

Contributors should:

- Share knowledge
- Review constructively
- Document decisions
- Support maintainability
- Help improve the platform

---

## Accountability

Every engineer is responsible for the quality of their contributions.

This includes:

- Testing changes
- Updating documentation
- Following standards
- Responding to review feedback
- Reporting issues honestly

---

# Expected Behavior

Examples of positive behavior include:

- Respectful technical discussions
- Constructive code reviews
- Evidence-based decision making
- Helping other contributors
- Sharing knowledge
- Improving documentation
- Reporting vulnerabilities responsibly
- Following engineering standards
- Accepting constructive feedback
- Prioritizing platform stability over personal preference

---

# Unacceptable Behavior

The following behaviors are not permitted.

## Harassment

Including but not limited to:

- Personal attacks
- Threats
- Intimidation
- Discrimination
- Offensive language
- Deliberate exclusion

---

## Disruptive Conduct

Examples include:

- Repeated off-topic discussions
- Spam
- Trolling
- Deliberate misinformation
- Hostile arguments
- Refusal to follow project procedures

---

## Security Violations

Examples include:

- Sharing confidential information
- Publishing credentials
- Introducing malicious code
- Circumventing security controls
- Unauthorized access attempts
- Deliberate policy violations

Security violations may result in immediate removal from the project.

---

## Unprofessional Engineering Practices

Examples include:

- Knowingly submitting broken code
- Ignoring documented standards
- Bypassing code review
- Skipping required testing
- Deliberately introducing technical debt
- Falsifying test results
- Concealing operational risks

---

# Engineering Discussions

Technical disagreements are expected.

Participants should:

- Present evidence.
- Explain trade-offs.
- Consider alternatives.
- Remain open to feedback.
- Document decisions.

Engineering decisions should be based on:

- Security
- Reliability
- Maintainability
- Performance
- Operational simplicity
- Long-term sustainability

---

# Code Review Etiquette

Reviewers should:

- Be respectful.
- Explain requested changes.
- Reference standards where appropriate.
- Focus on the code, not the contributor.
- Encourage learning and collaboration.

Contributors should:

- Receive feedback professionally.
- Ask clarifying questions when necessary.
- Update submissions promptly.
- Avoid defensive or confrontational responses.

---

# Reporting Concerns

If you experience or witness behavior that violates this Code of Conduct:

1. Document the incident.
2. Notify the Platform Engineering Team.
3. Provide relevant evidence when possible.
4. Avoid public confrontation while the issue is under review.

Reports will be handled confidentially where appropriate.

---

# Enforcement

Maintainers may take appropriate action, including:

- Informal guidance
- Formal warning
- Temporary suspension
- Removal of repository access
- Revocation of contributor privileges
- Escalation to organizational leadership

The response will depend on the severity and frequency of the violation.

---

# Good Faith Participation

Contributors acting in good faith will be treated fairly, even when mistakes occur.

Constructive feedback and continuous improvement are encouraged.

---

# Governance

The Platform Engineering Team is responsible for interpreting and enforcing this Code of Conduct.

Questions regarding interpretation should be directed to the maintainers before taking action.
